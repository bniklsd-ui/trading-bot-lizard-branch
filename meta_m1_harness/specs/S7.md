# S7 — Abstain-Report-CLI (nur Referenz-Build, ungemessen)

> **Self-contained spec.** Diese Datei wird als Prompt-Text in einen Bake-off-Trial injiziert
> — **allerdings nur im Referenz-Build (Claude Code, Step 6), nicht in den gemessenen
> Bake-off-Trials.** Lies keine anderen Specs oder den M1-Plan, um sie zu verstehen.
> **Voraussetzung:** S1 (`AbstainRecord`, `AbstainReason`), S3 (`AbstainStore`) existieren
> bereits im Repo.

## Gemeinsame Konventionen (für alle S0–S7 Specs)

Python, `from __future__ import annotations`, Type-Hints, Docstrings, pytest mit Mocks (keine
Netzwerk-Calls), stderr-Logging, eine Datei = eine Verantwortung. Ziel-Paket:
`phase10_v3/abstain_lessons/` mit `tests/` daneben (`phase10_v3/tests/`).

## Ziel

Eine deterministische CLI, die eine Zusammenfassung der Abstain-Records auf stdout ausgibt —
kein Netz, keine AI.

## Datei

- `phase10_v3/scripts/abstain_report.py`
- `phase10_v3/tests/test_report.py`

## Exakte Namen / Verhalten

- Skript nimmt einen `--db`-Arg (Pfad zur SQLite-DB).
- Gibt auf stdout aus: Counts je `AbstainReason`, die letzten N Records (Kurzform), Anteil der
  Records mit gesetzter Lehre (`lesson_extracted=True`).
- Rein deterministisch — kein Netzwerk-Call, kein LLM-Aufruf.

## Tests

`test_report.py` — Golden-Output-Test gegen eine `tmp_path`-DB mit bekannten Fixture-Records:
exakter erwarteter stdout-Text wird assertet.

## Gate-Kommando

```
pytest phase10_v3/tests/test_report.py -q
```

## Scope-Grenzen

Nur `abstain_report.py` + sein Test. Kein Wiring in andere Phasen, kein Scheduler-Hook.
